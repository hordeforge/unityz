# Project documentation

`INDEX.md` is generated by `scripts/docs-index.sh` and links the durable
project records.

- `features.md` is the capability reference for the tool itself: what
  reads what, what extracts what, and the verification evidence. The
  README summarizes it.
- `WORKFLOW.md` explains the complete delivery lifecycle and how the records
  below fit together.
- `locks.md` defines the lease contract for an exclusive shared resource.
- `.local/project-kit.toml` configures portable commands, leases, worktrees,
  and optional backups for this machine; it is intentionally not committed.
- `ROADMAP.md` is the short navigation view: what is current, planned, and
  shipped. Link to the underlying PRD or ADR rather than duplicating it.
- `prds/` contains feature contracts. Start with `prds/TEMPLATE.md`.
- `adrs/` contains durable technical decisions. Start with `adrs/TEMPLATE.md`.
- `rfcs/` contains decisions not yet made: the options, their implications,
  and a confidence-scored recommendation. Start with `rfcs/TEMPLATE.md`.
- `research/` contains evidence with read dates - what exists and how
  confident the finding is. Start with `research/TEMPLATE.md`.
- `plans/` contains execution plans for non-trivial work. Start with
  `plans/TEMPLATE.md`.
- `handovers/` captures a safe continuation point for another session. Start
  with `handovers/TEMPLATE.md`.
- `reviews/` contains dated review records with evidence and follow-up. Start
  with `reviews/TEMPLATE.md`.
- `reports/` contains operational reports: confirmed bugs, evidence-led
  investigations, and blameless incident postmortems, with their resolution and
  verification. Create one with `.local/scripts/new-doc bug <title>`,
  `.local/scripts/new-doc investigation <title>`, or
  `.local/scripts/new-doc postmortem <title>`; the inventory lives in
  `reports/README.md`.
- `prompts/` contains reusable prompts that define a review lens. Start with
  `prompts/general-review.md` or `prompts/change-review.md` and add a narrower
  prompt only when a project repeats a specialized review.
- `agent-rules/` contains the reusable collaboration policy and optional
  repository workflow rules. Start with `agent-rules/general.md`; use
  `agent-rules/repository-rule-template.md` when defining a repository rule.

Every record is written to be scanned, not studied: keep paragraphs short
(one fact or step each) and use bullet lists for enumerations.
`.local/scripts/project-kit.py docs-check` flags overlong wall-of-text
paragraphs in every document under `docs/`.

After adding, renaming, or materially changing these records, run:

```sh
scripts/docs-index.sh
```
